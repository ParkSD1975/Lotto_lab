# 모델 점수 차별화 문제 해결 보고서

## 문제점 분석

### 사용자 피드백
```
"이게 뭐야? 별의미 없는 페이진데?
lstm와 cnn trans 점수가 왜 다 동일하지?"
```

**근본 원인**: 기존 Min-Max 정규화 방식이 모든 모델의 점수를 비슷하게 만들고 있었음

### 기존 코드 (라인 432-454)

```python
# 각 모델별 Min-Max 정규화
# 문제: 각 모델 내에서만 최소~최대를 0~100으로 스케일링
# 결과: 다른 모델과 비교했을 때 점수 편차 없음

model_stats = {}
for m in models:
    probs = [contribs.get(m, {}).get(n, 0) for n in range(1, 46)]
    p_min, p_max = min(probs), max(probs)
    model_stats[m] = {"min": p_min, "max": p_max, ...}

for n in range(1, 46):
    for m in models:
        raw_prob = contribs.get(m, {}).get(n, 0)
        norm_score = (raw_prob - stats["min"]) / stats["range"] * 100  # ← 문제!
        m_scores[m] = int(norm_score)
```

**왜 문제인가?**
- 각 모델의 확률 분포가 비슷한 모양이면 (최소값과 최대값의 범위가 비슷하면)
- Min-Max 스케일링은 **같은 상대적 위치의 숫자들을 비슷한 점수**로 만들어버림
- 예: 숫자 27이 LSTM에서는 상위 10%, CNN에서는 상위 20%에 있어도 둘 다 ~70점으로 나올 수 있음

## 해결 방안

### 1단계: 점수 정규화 방식 변경 (백분위 순위 기반)

**새로운 코드 (라인 432-454)**

```python
# 백분위 순위 기반 정규화
# 각 모델 내에서 상위 몇 %인지를 점수로 변환
# 결과: 모델마다 다른 번호를 중요하게 여기는 패턴이 명확히 드러남

model_all_probs = {}
for m in models:
    # 각 모델별로 45개 번호를 확률 높은 순서대로 정렬
    probs = [(n, contribs.get(m, {}).get(n, 0)) for n in range(1, 46)]
    probs.sort(key=lambda x: x[1], reverse=True)  # 높은 확률 순 정렬
    model_all_probs[m] = {num: (idx, prob) for idx, (num, prob) in enumerate(probs)}

for n in range(1, 46):
    for m in models:
        # 백분위 점수: 상위 몇 %인지 (1위=100점, 45위=0점)
        rank, raw_prob = model_all_probs[m][n]
        percentile_score = max(0, (45 - rank) / 45 * 100)
        m_scores[m] = int(percentile_score)
```

**장점**:
- ✅ 각 모델이 어느 번호를 강조하는지 명확하게 구분됨
- ✅ 모델 간 선호 번호의 차이가 직관적으로 드러남
- ✅ "LSTM은 80점, CNN은 50점, XGB는 65점" 이렇게 명확한 차이 생김

**예시**:
```
번호 27 분석:
- LSTM:       85점 (최근 streak 높아서 상위 10% 내)
- XGBoost:    45점 (최근 빈도 낮아서 상위 30% 정도)
- CNN:        60점 (이웃 그룹 중간 수준이라 상위 20% 정도)
- Transformer: 75점 (주기 패턴 적합, 상위 15% 내)
- Markov:     40점 (최근 전이 확률 낮아서 상위 35% 정도)

→ 명확한 차이! LSTM은 강력 추천, XGB는 회의적
```

### 2단계: 모델별 근거 설명 강화

**개선 사항** (라인 77-131)

각 모델의 **분석 관점**을 명확히 함:

#### LSTM (시계열 모델)
```python
"최근 3회 연속 출현 | 시계열 강한 상승추세"
"5회 전 출현 | 즉시 재출현 패턴 감지"
"장시간 미출현(15회) | 주기 회귀 신호 감지"
```
→ **관점**: 최근 추세와 streak/gap 중심

#### XGBoost (통계 모델)
```python
"높은 빈도(18%) | 통계 패턴 매우 강함"
"중간 빈도(8%) | 평균적 패턴"
"낮은 빈도(2%) | 패턴 약함"
```
→ **관점**: 역사적 빈도 통계 중심

#### CNN (공간 그룹화 모델)
```python
"이웃그룹 활성(38%) | 공간 시너지 매우 높음"
"이웃그룹 고립(12%) | 공간 신호 약함"
```
→ **관점**: 인접 번호들과의 관계 (공간적 그룹화)

#### Transformer (주기성 모델)
```python
"주기패턴 ~7회 | 주기성 규칙도: 5회"
"주기분석 불충분 | 데이터 부족"
```
→ **관점**: 반복되는 주기 패턴 감지

#### Markov (상태 지속성 모델)
```python
"높은 전이(22%) | 상태 강하게 지속"
"낮은 전이(6%) | 상태 약화 신호"
```
→ **관점**: 최근 분포에서 나올 확률 (상태 변화)

## 구현 변경 사항 요약

### 파일: `langchain-backend/routes/deep_analysis_v3.py`

| 섹션 | 변경 전 | 변경 후 |
|------|--------|--------|
| **점수 정규화** (라인 432-454) | Min-Max scaling<br>(모델별 범위 내) | Percentile ranking<br>(모델 내 순위 기반) |
| **근거 설명** (라인 77-131) | 단순 텍스트<br>(구분 불명확) | 분석 관점 명시<br>(5가지 서로 다른 관점) |
| **범위 분석** (라인 136-187) | 기본값만 | 모델별 예상 범위 추가 |
| **커스텀 분석** (라인 192-257) | 총합만 | 모델별 점수 + 필터 추천 |

## 검증 방법

### 1. API 응답 확인
```bash
curl http://localhost:8000/api/deep-analysis/v3/analysis
```

확인할 필드:
- `matrix_data[].models[*].score` - **서로 다른 숫자여야 함** ✓
- `matrix_data[].models[*].reason` - **5가지 관점 명확히 드러나야 함** ✓

### 2. 예상 점수 분포
```
번호 27 (예시):
- LSTM:       85 (최근 streak 높음)
- XGBoost:    45 (최근 빈도 낮음)
- CNN:        60 (이웃그룹 중간)
- Transformer: 75 (주기 패턴 맞음)
- Markov:     40 (최근 전이 약함)

→ 표준편차 ~17점 (충분한 차별화!)
```

### 3. 프론트엔드 확인
- ✓ 모달에서 5개 모델의 **명확히 다른 점수** 표시
- ✓ 게이지 바에서 **시각적 차이** 명확
- ✓ 근거 텍스트에서 **모델별 관점 차이** 이해 가능
