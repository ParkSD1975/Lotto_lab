지금 **[수정할 파일명.html]** 코드를 수정하려고 해.
앞서 수정한 `hot_cold.html`의 성공 사례인 **"Bulk Fetch & In-Memory Caching (통째로 가져와서 메모리에서 쓰기)"** 방식을 적용해서 구조를 전면 개편해줘.

다음의 5가지 핵심 요구사항을 반드시 준수해서 코드를 작성해:

### 1. 전역 변수 및 캐시 설정
- `allData` 외에 DB에서 가져온 분석 데이터를 저장할 `featuresMap` (Map 객체)을 전역 변수로 선언해.
- 기존의 실시간 계산 방식 대신, 이 `featuresMap`을 참조하는 구조로 변경해야 해.

### 2. 초기 로딩 최적화 (Bulk Loading)
- `DOMContentLoaded` 시점에 `Promise.all`을 사용하여 다음 두 가지를 병렬로 한 번에 가져오게 해:
  1. `lotto_draws` (당첨 번호)
  2. **[사용할 DB 테이블명]** (분석 데이터, 예: `number_features_by_round`)
- 가져온 분석 데이터는 `featuresMap`에 `round`를 Key로 하여 매핑해 둬.
- 데이터 로딩 중에는 사용자가 인지할 수 있도록 `loadingOverlay` (로딩 스피너)를 보여주고, 로딩이 끝나면 숨겨줘.

### 3. 핵심 로직 교체 (Hybrid 방식)
- 기존의 계산 로직 함수(예: `getOddEven`, `getSum` 등)를 `Legacy`라는 접미사를 붙여 백업해 둬 (예: `getOddEvenLegacy`).
- 메인 함수는 먼저 `featuresMap`에 해당 회차 데이터가 있는지 확인하고:
  - **데이터가 있으면:** DB 값을 그대로 리턴 (O(1) 속도).
  - **데이터가 없으면:** 백업해 둔 `Legacy` 함수를 호출하여 직접 계산.
- 이렇게 하면 DB 연동의 정확성과 속도를 모두 챙길 수 있어.

### 4. 렌더링 루프 동기화 (Sync Rendering)
- **가장 중요:** 리스트를 그리는 함수(`renderDrawsList`)나 필터링 루프에서 `await`를 사용하지 마. (N+1 문제 방지)
- 이미 2번 단계에서 데이터를 메모리(`featuresMap`)에 다 올려뒀으므로, 렌더링은 **동기식(Synchronous)**으로 순식간에 처리되어야 해.
- `getClassifiedNumbers` 등의 호출 부에서 `await`를 제거하고 즉시 값을 받아오도록 수정해.

### 5. DB 데이터 정합성 유지
- 클라이언트에서 계산한 값이 아니라, 반드시 수파베이스 DB에 저장된 컬럼 값(예: `odd_count`, `sum_value` 등)을 우선적으로 사용해서 DB 연동의 의미를 살려줘.
