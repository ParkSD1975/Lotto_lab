# 통합 필터 규칙 엔진 설계 계획

## 1. 현재 문제점 진단

페이지마다 동일 로직이 **중복·표류**하고 있습니다:

| 항목 | 현 상태 |
|---|---|
| 저장/로드 함수 | 각 페이지마다 `saveFilterSettings` / `loadFilterSettings` 자체 구현 (10+ 파일) |
| 저장 키 | 통일 안 됨 (`composite_number_filter` vs `composite_count` vs `composite_filter`) |
| 자체 저장 락 | `_primeSelfSaving`, `_compositeSelfSaving`, `_dashSelfSaving` 등 페이지마다 파편화 → 경쟁 상태 발생 |
| `recent10FilterActive` 흐름 | 페이지마다 다르게 구현, 신규 회차 감지 로직 중복 |
| `markManual` / `deactivateRecent10IfActive` | 페이지마다 미묘하게 다름 (소수/합성수 모두 동일 버그 있었음) |
| 로그아웃 리셋 | 페이지마다 다르게 처리 또는 누락 |
| 조합 저장 시 필터 스냅샷 | 존재 여부·DB 컬럼·UI 모두 확인 필요 |

## 2. 제안 아키텍처

```
js/filter/
├── FilterRuleEngine.js     ← 핵심 (단일 진입점)
├── FilterSchema.js         ← 필터 정의(메타데이터) 레지스트리
├── FilterLifecycle.js      ← 로그아웃/로그인/신규회차/수동변경 이벤트
├── FilterStorage.js        ← Utils.saveFilter 래퍼 + 키 정규화 + 락 통합
├── FilterSnapshot.js       ← 조합 저장용 전체 스냅샷 + 복원
└── adapters/
    ├── PrimeAdapter.js
    ├── CompositeAdapter.js
    ├── HotColdAdapter.js
    └── ...                 ← 각 페이지 DOM 바인딩만 담당
```

## 3. 핵심 모듈 책임

### 🔹 FilterSchema.js — 필터 메타데이터
각 필터를 **선언적**으로 정의:
```js
{
  key: 'composite_count',
  type: 'discrete',                  // discrete | range | ratio | numbers
  defaultValue: [0,1,2,3,4,5,6],     // 로그아웃 시 적용
  resetOnNewRound: 'recent10',       // 신규 회차 시 동작
  pageUrl: 'composite_number.html',
  legacyKeys: ['composite_filter','composite_number_filter']
}
```

### 🔹 FilterStorage.js — 저장 단일 진입점
- `save(key, settings, enabled, targetRound)` / `load(key, targetRound)`
- **하나의 락 변수**로 통합 (`_engineSaving`)
- 저장 키 자동 정규화 (legacy → standard)
- StorageEvent + BroadcastChannel 자체 송신 무시

### 🔹 FilterLifecycle.js — 4가지 이벤트 처리

| 이벤트 | 트리거 | 동작 |
|---|---|---|
| `LOGOUT` | Supabase 로그아웃 감지 | 모든 필터 → schema.defaultValue, 제외/고정수 삭제, recent10 비활성 |
| `LOGIN` | 로그인 후 데이터 로드 | DB 마지막 저장값 → 모든 필터 적용 |
| `NEW_ROUND` | `lotto_draws` 최신 회차 변경 감지 | 제외/고정수 삭제, 수동값 삭제, recent10 패턴 자동 적용, recent10 활성화, 하이라이트 ON |
| `MANUAL_OVERRIDE` | 사용자가 버튼/입력 직접 조작 | recent10 비활성, 하이라이트 OFF, isManual=true |

이전 페이지마다 흩어진 `markManual` / `deactivateRecent10IfActive` / `checkAndResetOnNewDraw` 가 모두 여기로 통합됩니다.

### 🔹 FilterRuleEngine.js — 외부 API
```js
FilterEngine.register(schema)
FilterEngine.getValue(key)
FilterEngine.setValue(key, value, { source: 'manual' | 'system' })
FilterEngine.toggleEnabled(key, bool)
FilterEngine.on('change', handler)   // UI 동기화용
FilterEngine.snapshot()              // 조합 저장용
FilterEngine.restore(snapshot)       // 조합 불러오기용
```

페이지/대시보드는 직접 localStorage 만지지 않고 **무조건 이 API만 호출**.

### 🔹 FilterSnapshot.js — 조합과 묶이는 스냅샷
- `snapshot()` → `{ filters: {key: {settings, enabled}}, basket: {fixed, excluded}, targetRound, savedAt }`
- 조합 저장 시 함께 Supabase 저장 (`saved_combinations.filter_snapshot` 컬럼)
- 조합 그룹 상세에서 **「필터 불러오기」 버튼** → `restore(snapshot)` 호출

## 4. 단계별 실행 로드맵

### **Phase 0: 사전 조사 (코딩 전)**
1. 모든 분석 페이지에서 사용 중인 필터 키 목록 수집 (15+ 키)
2. Supabase `saved_combinations` 테이블에 `filter_snapshot` 컬럼 존재 여부 확인
3. 조합 페이지에서 「필터 불러오기」 UI 버튼 존재 여부 확인 → 없으면 신규 추가 항목으로 등록
4. 로그아웃 감지 훅이 어디에 있는지 확인 (없으면 신규)

### **Phase 1: 엔진 골격 구축**
- `FilterSchema.js` — 모든 15+ 필터 메타데이터 카탈로그
- `FilterStorage.js` — `Utils.saveFilter` 래핑 + 키 정규화
- `FilterRuleEngine.js` — register/get/set/snapshot API
- 단위 테스트 (브라우저 콘솔에서 수동 테스트 가능한 정도)

### **Phase 2: 라이프사이클 통합**
- `FilterLifecycle.js` — 4가지 이벤트 처리
- 로그아웃 / 신규회차 감지 훅 1곳으로 통합
- 페이지 어떤 곳에서도 동일하게 동작 보장

### **Phase 3: 페이지 마이그레이션 (점진적)**
1. 소수, 합성수 (현재 가장 망가진 페이지) → 우선
2. 핫/콜드, AC, 끝수, 배수 등 단순 필터
3. 미출현 그룹, 9궁, 로또용지 등 복합 필터
4. 마지막에 대시보드(`filter_dashboard.js`)도 동일 엔진 사용

각 페이지에서 제거되는 코드:
- `saveFilterSettings` / `loadFilterSettings`
- `_xxxSelfSaving` 락
- `markManual` / `deactivateRecent10IfActive` / `checkAndResetOnNewDraw`
- 페이지별 storage 이벤트 리스너

→ 모두 어댑터(수십 줄)로 대체

### **Phase 4: 조합 스냅샷 기능**
- DB 마이그레이션: `saved_combinations.filter_snapshot JSONB` 컬럼 추가 (없으면)
- 조합 저장 시 `FilterEngine.snapshot()` 호출 → 함께 저장
- 조합 그룹 상세에 **「적용 필터 불러오기」 버튼** 추가
- 클릭 시 `FilterEngine.restore(snapshot)` → 모든 필터 일괄 복원

### **Phase 5: 검증 및 정리**
- 모든 페이지에서 4가지 라이프사이클 시나리오 수동 테스트
- 레거시 키 마이그레이션 (`composite_number_filter` 등) 자동 변환 후 1회성 정리
- 중복 코드 삭제, 문서화

## 5. 기대 효과

| 현재 | 개선 후 |
|---|---|
| 페이지마다 저장 버그 발생 (소수, 합성수 사례) | 엔진 1곳만 검증하면 모든 페이지 일관 |
| 키 표류 (3가지 키로 분산) | 단일 표준 키 + 자동 마이그레이션 |
| 라이프사이클 동작 페이지마다 다름 | 4가지 이벤트로 명세화 |
| 조합-필터 연결 불확실 | 스냅샷으로 명시적 보장 |
| 페이지 추가 시 필터 로직 복붙 | 스키마 1줄 등록 + 어댑터 수십 줄 |

## 6. 사용자 요구사항 매핑

| 요구사항 | 처리 위치 |
|---|---|
| 1. 로그아웃 시 기본값(구간=최소~최대, 범위=0~6, 비율=전체) | `FilterLifecycle.LOGOUT` + `FilterSchema.defaultValue` |
| 2. 로그인 시 마지막 저장값 적용 | `FilterLifecycle.LOGIN` + `FilterStorage.load` |
| 3. 회차 업데이트 시 제외/고정수 삭제 + 수동필터 삭제 + 최근10회차 자동적용 + 활성화 + 하이라이트 | `FilterLifecycle.NEW_ROUND` |
| 4. 수동 변경 시 최근10 비활성 + 하이라이트 제거 | `FilterLifecycle.MANUAL_OVERRIDE` |
| 5. 조합 저장 시 필터 스냅샷 + 불러오기 버튼 | `FilterSnapshot` (Phase 4) |
