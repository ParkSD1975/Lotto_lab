# 프로젝트 AI 보조 규칙 (rules1.md)

## 1. 역할 및 커뮤니케이션 (Role & Communication)
- **대상 사용자**: 비전문 개발자 (도메인 전문가).
- **언어**: 항상 자연스럽고 이해하기 쉬운 **한국어**로 응답할 것.
- **설명 방식**: 불필요한 개발 전문 용어(Jargon)는 피하고, 일상적인 비유를 사용하여 기술적 개념을 쉽게 설명할 것.
- **사고 과정**: 코드를 생성하거나 수정할 때, 코드를 기재하기 전에 항상 단계별로 생각하고 로직을 명확히 설명할 것.

## 2. 코드 수정 및 안전성 (Code Modification & Safety - CRITICAL)
- **부분 수정**: 요청받은 특정 부분만 수정하며, 나머지 코드는 **절대** 건드리지 말 것.
- **리팩토링 금지**: 명시적인 요청이 없는 한 파일 전체를 재작성하거나 리팩토링하지 말 것 (원본 유지).
- **주석 표시**: 코드 업데이트 시 `// [수정]` 또는 `// [추가]` 등의 주석을 달아 변경된 부분을 사용자가 직관적으로 찾을 수 있도록 할 것.

## 3. 기술 스택 컨텍스트 (Tech Stack Context)
- **프론트엔드**: CDN 기반의 Vue 3, Bootstrap 5, 단일 HTML 파일 구조 (예: `ai_deep_learning.html` 등).
- **백엔드/DB**: Python 로컬 AI 서버, Supabase JS (CDN 연동).
- **개발 환경 제약 조건**: 명시적인 지시가 없는 한 `npm install`이나 빌드 도구 (Vite/Webpack/Node.js 등) 환경 구성을 제안하지 말고, CDN이 호환되는 순수(Vanilla) 방식으로 해결책을 제시할 것.

## 4. AI 에이전트 행동 지침 및 자동화 (Agent Behavior & Auto-Execution)
- **사전 권한 (자동 실행)**: 로컬 라이브 서버 구동, 단순 Git 명령어 등 시스템을 파괴하지 않는 안전한 터미널 명령어는 사용자에게 매번 허락을 구하지 않고 즉시 자동 실행한다.
- **오류 자체 해결 (Self-Correction)**: 명령어 실행 또는 코드 적용 시 오류가 발생하면, 사용자에게 곧바로 묻기 전에 스스로 오류 로그를 분석하고 자동으로 1~2차 수정을 시도한다.

## 5. 주요 작업 워크플로우 (Workflows)
### 🚀 새로운 기능 추가 시 (Feature Addition Workflow)
1. 대상 HTML/Python 문서를 분석하여 현재의 Vue `setup()` 구조나 백엔드 로직 흐름을 파악한다.
2. 필요한 작업 단계(UI 템플릿 변경, 새로운 반응형 변수 선언, DB/API 호출 등)를 개요로 정리한다.
3. 사용자가 계획을 파악할 수 있도록 짧은 확인을 받는다.
4. 코드를 제공할 때, 기존의 **어느 함수 내부** 또는 **어느 줄(Line)**에 코드를 삽입해야 하는지 정확한 위치와 함께 스니펫을 제공한다.

### 🐛 버그 수정 시 (Bug Fix Workflow)
1. 문제를 일으키는 파일 내의 **정확한 코드 라인이나 로직 블록을 찾아낸다.**
2. 버그가 발생한 **'이유(Why)'**를 쉬운 한국어 평문으로 설명한다. (예: "계산이 시작되기 전에 서버에서 데이터를 다 받아오지 못했습니다.")
3. 디버깅이 필요할 경우 콘솔/터미널 명령어를 통해 스스로 상황을 확인한다.
4. 코드를 통째로 바꾸지 말고, 문제를 해결할 수 있는 **최소한의 정확한 코드 변경점**만 제공한다.
